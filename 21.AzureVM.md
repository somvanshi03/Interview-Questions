# Azure Virtual Machine interview questions

### Part 1: Basic to Intermediate Level

#### 1. What is an Azure Virtual Machine (VM)? What are the core components?
**Answer:**
An Azure Virtual Machine is an Infrastructure-as-a-Service (IaaS) offering that allows you to run virtualized, on-demand computer systems. It gives you the flexibility of virtualization without having to buy and maintain the physical hardware.
**Core Components:**
- **Compute:** The VM itself (CPU, RAM) – defined by the VM Size (e.g., D2s_v3).
- **Storage:** Disks attached to the VM (OS Disk, Data Disk, Temporary Disk).
- **Networking:** Virtual Network (VNet), Network Interface Card (NIC), IP Addresses, and Network Security Groups (NSGs) for traffic control.
- **Operating System:** Windows or Linux images provided by Azure or custom images.

#### 2. Explain the difference between an Availability Set and an Availability Zone.
**Answer:**
- **Availability Set:** A logical grouping of VMs that allows Azure to understand how your application is built to provide redundancy and availability. It ensures that VMs are distributed across multiple:
    - **Update Domains (UD):** Groups of VMs that can be rebooted at the same time during planned maintenance.
    - **Fault Domains (FD):** Groups of VMs that share a common power source and network switch. It protects against physical hardware failures within the same datacenter.
- **Availability Zone:** Physically separate locations (datacenters) within an Azure region. Each zone has its own independent power, cooling, and networking. It protects against a datacenter-level failure.

#### 3. What is an Azure Compute Gallery (formerly Shared Image Gallery)?
**Answer:**
The Azure Compute Gallery is a service that helps you build, manage, and share a large number of VM images across your organization. It allows you to version your images and replicate them to different regions quickly.
- **Benefits:**
    - **Versioning:** Maintain multiple versions of the same image.
    - **Replication:** Easily replicate images to different regions for global deployment.
    - **Sharing:** Share images within your tenant or across tenants using RBAC.
    - **Scalability:** Supports massive scale deployments.

#### 4. What is the difference between Managed Disks and Unmanaged Disks?
**Answer:**
- **Unmanaged Disks:** The user is responsible for the storage accounts where the Virtual Hard Disk (VHD) files are stored as page blobs. You have to manage storage account limits (e.g., 20,000 IOPs per account), which can become complex at scale.
- **Managed Disks:** Azure manages the storage accounts for you. You just specify the disk type (HDD, Standard SSD, Premium SSD, Ultra Disk), size, and performance tier. It handles scalability, availability, and security, simplifying disk management.

#### 5. How do you resize the OS or Data disk of a running VM?
**Answer:**
You can resize a managed disk even while the VM is running (if the disk supports live resize).
**Steps:**
1.  Go to the VM in the portal, stop it, or keep it running.
2.  Navigate to **Disks**.
3.  Select the disk you want to expand.
4.  On the disk page, go to **Size + performance**.
5.  Increase the size in the GUI. *Note: You can increase the size, but you cannot decrease it.*
6.  After the disk is resized in Azure, you must connect to the OS (e.g., using Disk Management in Windows or `resize2fs`/`xfs_growfs` in Linux) to extend the volume to utilize the new space.

#### 6. What is a Snapshot? How is it different from an Image?
**Answer:**
- **Snapshot:** A point-in-time, read-only copy of a *specific disk* (OS or Data). It is dependent on the original disk's storage location. It's used for:
    - Backing up a specific disk.
    - Creating a new managed disk from a specific point in time.
- **Image:** A template that contains the OS disk and *optionally* one or more data disks. It also stores additional metadata. It is independent and can be used to create *new* VMs from scratch. Images are the building blocks for scaling out.

### Part 2: Advanced Level

#### 7. Explain Azure Dedicated Host. Why would you use it over a regular VM?
**Answer:**
Azure Dedicated Host provides physical servers dedicated to your Azure subscription. You have visibility and control over the server hardware.
- **Use Cases:**
    - **Compliance:** Meeting regulatory compliance requirements that mandate physical isolation.
    - **Licensing:** Using your own Windows Server or SQL Server licenses with full license mobility and no hypervisor layer overhead (maximizing Azure Hybrid Benefit).
    - **Visibility:** You can see the server's health and maintenance history.
- **Difference from Regular VM:** In a regular VM, you share the physical host with other customers (multi-tenant). With Dedicated Host, the host is yours and yours alone.

#### 8. What is a Host Group and a Capacity Reservation?
**Answer:**
- **Host Group:** A logical grouping of Dedicated Hosts. You create a host group first and then add Dedicated Hosts to it. Host groups are used to manage fault domain awareness for dedicated hosts across availability zones or within a datacenter.
- **Capacity Reservation:** A feature that allows you to reserve compute capacity in an Azure region or an Availability Zone for any duration. Unlike Dedicated Hosts, you don't get the physical server, but you ensure that VM capacity is guaranteed when you need it.
    - **Key Benefit:** Eliminates the risk of "capacity errors" (SKU not available) during failovers or scaling events.

#### 9. How do you change the Compute Family (VM Size) of an existing VM, for example, from D-series to E-series?
**Answer:**
You cannot directly "change" the family. You have to resize the VM to a different size. The VM must be deallocated (stopped) to resize to a different hardware family.
**Steps:**
1.  **Stop (Deallocate)** the VM in the portal or using CLI/PowerShell. This removes the VM from the current host.
2.  Navigate to the VM's **Size** blade.
3.  Select a new size from the desired family (e.g., from D2s_v3 to E2s_v3).
4.  Click **Resize** and start the VM again.
- **Constraint:** The new size must be available in the same region and in the cluster that has capacity. If not available, you might need to delete the VM but keep the disks, and recreate the VM using those disks.

#### 10. What are Azure Arc-enabled servers? How do they relate to Azure VMs?
**Answer:**
Azure Arc-enabled servers extend Azure management and governance capabilities to any server hosted *outside* of Azure (on-premises, other clouds, edge locations).
- **Relation:** While Azure VMs are born in Azure, Arc-enabled servers are "onboarded" to Azure. Once onboarded, they appear as hybrid machines in the Azure portal with an Azure Resource Manager ID. You can then manage them using Azure tools like:
    - Azure Policy (e.g., enforce log analytics agent installation).
    - Microsoft Defender for Cloud.
    - Tagging and resource organization.
- **Key Point:** Arc turns non-Azure machines into Azure resources for management purposes.

#### 11. What is a Disk Encryption Set (DES)? Why is it necessary for encryption at host or customer-managed keys (CMK)?
**Answer:**
A Disk Encryption Set (DES) is a resource that references the Key Vault containing the Customer-Managed Keys (CMK) used for encrypting managed disks. It acts as a "pointer" or a "broker" between the compute resource (VM) and the key in the Key Vault.
- **Why is it needed?** It allows Azure to use the CMK to encrypt the disks on behalf of the VM. It includes the concept of **Federated Identity**, where the DES is assigned a system-assigned managed identity. This identity is granted permissions (wrap/unwrap) in the Key Vault, allowing the disk encryption process to occur securely.

#### 12. Explain Azure Automanage for virtual machines.
**Answer:**
Azure Automanage is a service that automates the onboarding, configuration, and management of best-practice Azure services for VMs. Once you enable Automanage for a VM, it automatically applies a specific configuration profile (e.g., "Production" or "Dev/Test") which includes:
- Enabling Backup.
- Enabling Update Management.
- Installing the Log Analytics agent and linking it to a workspace.
- Configuring Microsoft Antimalware.
- It manages the lifecycle of these services, ensuring they stay in compliance with the configured state.

#### 13. How does Azure Monitor and Log Analytics help with VM Logs and Events Management?
**Answer:**
- **Data Collection:** By installing the Log Analytics agent (or the new Azure Monitor Agent) on the VM, you can collect:
    - **Windows Event Logs:** (e.g., System, Application, Security logs).
    - **Syslog:** From Linux machines.
    - **Performance Counters:** CPU, Memory, Disk I/O.
- **Storage:** This data is sent to a **Log Analytics Workspace**, which is a centralized data repository.
- **Analysis & Visualization:**
    - **Log Queries:** You can use Kusto Query Language (KQL) to search for specific errors (Event ID 5000) or trends.
    - **Alerts:** Set up alerts to fire when a specific event is logged (e.g., disk full warning).
    - **Workbooks:** Create rich visual reports of your log data.

#### 14. What is Azure Compute Fleet? How does it differ from Virtual Machine Scale Sets (VMSS)?
**Answer:**
Azure Compute Fleet is a service that acts as a *super-scheduler* for VM capacity across different VM types, Availability Zones, and pricing models (On-Demand and Spot).
- **Key Features:**
    - **Multi-VM Type:** You can request a fleet of VMs specifying different sizes (e.g., D2s_v3, D4s_v3, E2s_v3) to increase your chances of acquiring capacity.
    - **Multi-Zone/Region:** It can spread the request across zones.
    - **Spot & On-Demand Mix:** You can define a percentage of Spot and On-Demand VMs.
- **Difference from VMSS:**
    - **VMSS** is designed for *scaling applications*. It automatically adds or removes identical VMs based on load (autoscaling).
    - **Compute Fleet** is designed for *capacity acquisition* and burst scenarios. It doesn't autoscale; it just helps you deploy a large set of VMs (maybe using Spot pricing) in the most efficient way possible. Think of Compute Fleet as a smart deployment tool, and VMSS as an autoscaling tool.

#### 15. Describe the process of Patch Management for Azure VMs.
**Answer:**
There are several ways to manage patches:
1.  **Azure Update Manager (Newer):** A unified service to manage and govern updates for all your machines (Azure VMs and Arc-enabled servers). It allows you to:
    - Assess patch compliance.
    - Install updates on-demand.
    - Configure recurring schedules for patching (maintenance configurations).
2.  **Azure Automation Update Management (Legacy):** Uses the Log Analytics agent and Azure Automation to assess and apply updates based on defined schedules.
3.  **Azure Policy:** Use built-in policies to ensure VMs are using a specific patch orchestration solution.
4.  **Automatic VM Guest Patching:** A feature on the VM properties that enables the VM to automatically download and apply critical and security patches during off-peak hours. The VM must have the `Microsoft.CPlat.Core.WindowsPatchAssessment` extension installed.
